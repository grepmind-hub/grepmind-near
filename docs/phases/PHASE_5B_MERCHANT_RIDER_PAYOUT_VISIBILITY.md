## Implementation

- Merchant Android reuses `GET /api/v1/merchant/businesses/{businessId}/finance/settlements`. The existing backend business-owner/active owner-or-manager check remains authoritative. The result now includes the linked transfer state, latest attempt state, transfer completion timestamp, and an explicit QA simulation disclosure; the endpoint remains unavailable outside isolated QA/test.
- Rider Android reads `GET /api/v1/rider/settlements`, registered behind the existing approved-rider authentication middleware. It scopes rows to the authenticated rider ID and is unavailable outside isolated QA/test. The response omits transfer IDs, beneficiary/bank data, provider names/identifiers, UTRs, audit internals, and COD cash liability.
- Both screens distinguish the transfer workflow result from actual bank credit and preserve the existing separation between rider earnings and COD cash liability. Neither view offers an approval, execution, or withdrawal action.
- OpenAPI documents the new rider read endpoint and payout-status fields. No migration was created.
